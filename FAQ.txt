Q1: Why did I see "[Errno 8] nodename nor servname provided, or not known" 
    during script generation?
--------------------------------------------------------------------------------
CAUSE:
This is a DNS lookup failure. The process could not resolve a hostname such as
`generativelanguage.googleapis.com`. Common causes include a restricted coding
agent sandbox, a disconnected network, VPN or proxy configuration, or a DNS
resolver problem. A browser or web-search tool may have network access even when
the shell process running the app does not; they are separate execution paths.

RESOLUTION:
1. Check that the Mac is online and that a normal Terminal can resolve the host:
   `nslookup generativelanguage.googleapis.com`
2. If it fails only inside a coding agent, approve the specific network-enabled
   command when the agent presents its permission prompt, or configure that
   agent's execution environment to allow outbound access. Organization policy
   or a managed sandbox administrator may control this setting.
3. To run the app outside the agent sandbox, open macOS Terminal, `cd` to this
   project, and run `./run_studio.sh`. This uses the Mac's normal network path;
   a VPN, firewall, proxy, or DNS problem can still block access.
4. If ordinary Terminal also fails, check VPN/proxy settings, DNS, and firewall
   rules, then retry the lookup. Do not add API keys to shell commands or logs.

Q2: What caused "TypeError: open() got an unexpected keyword argument 'metadata_errors'"
    in faster-whisper?
--------------------------------------------------------------------------------
CAUSE:
Faster-whisper's audio decoder (`faster_whisper/audio.py`) historically passed 
`metadata_errors="ignore"` to PyAV's `av.open()` method. 
In PyAV version 19.x (released in 2026), the deprecated `metadata_errors` keyword 
argument was completely removed from `av.open()`, causing a hard crash whenever 
Whisper decoded an audio or video stream.

RESOLUTION:
In `core/transcribe.py`, we implemented a zero-overhead compatibility monkey-patch 
before Whisper initializes:
```python
import av
_orig_av_open = av.open
def _safe_av_open(*args, **kwargs):
    kwargs.pop("metadata_errors", None)
    return _orig_av_open(*args, **kwargs)
av.open = _safe_av_open
```
This safely strips the unsupported argument, allowing `faster-whisper` to decode 
all media seamlessly with PyAV 19+ without needing to downgrade packages.

Q3: Why did `youtube-transcript-api` throw "AttributeError: type object 
    'YouTubeTranscriptApi' has no attribute 'list_transcripts'"?
--------------------------------------------------------------------------------
CAUSE:
In `youtube-transcript-api` version 1.2+ (2026 release), the API transitioned 
from static class methods to instance methods (`api = YouTubeTranscriptApi(); 
api.fetch(video_id)`), making legacy static calls fail.

RESOLUTION:
In `core/ingest.py`, `fetch_youtube_captions()` was updated to handle both 
interfaces:
It first attempts the new instance method `YouTubeTranscriptApi().fetch(video_id)`, 
and gracefully falls back to static methods if an older version is present. 
Snippets are extracted with exact timestamp ranges and assembled cleanly.

--------------------------------------------------------------------------------
Q4: Why did Whisper fail with "LocalEntryNotFoundError" when offline?
--------------------------------------------------------------------------------
CAUSE:
By default, `faster-whisper` checks HuggingFace Hub on initial load to see if a 
newer snapshot exists. If an internet connection or HuggingFace access is 
unavailable, HuggingFace Hub throws a `ConnectError` or `LocalEntryNotFoundError`, 
even if the weights were already downloaded.

RESOLUTION:
In `core/transcribe.py`, `get_whisper_model()` now scans the local HuggingFace 
hub cache directory (`~/.cache/huggingface/hub/models--Systran--faster-whisper-*`) 
for existing downloaded snapshots. If a local snapshot directory exists, it loads 
directly from the absolute local path. This enables 100% offline transcription 
with zero network pinging.

--------------------------------------------------------------------------------
Q5: How was the deprecation of `google.generativeai` handled?
--------------------------------------------------------------------------------
CAUSE:
Google officially deprecated the legacy `google.generativeai` library in favor of 
the modern `google-genai` SDK.

RESOLUTION:
In `core/model_router.py`, the code uses `from google import genai` and 
`from google.genai import types`. The client is initialized with 
`client = genai.Client(api_key=api_key)`, and models are dynamically discovered 
using `client.models.list()`.

Q6: What happens if Google Gemini hits a rate limit (HTTP 429)?
--------------------------------------------------------------------------------
SYMPTOMS:
You receive an alert or banner: "Rate limit detected. Automatically switched..."

HOW THE APP HANDLES IT:
Google's free-tier has rate limits on Requests-Per-Minute (RPM). Rather than 
failing your podcast generation, our Dynamic Model Router automatically:
1. Detects the `429 (ResourceExhausted)` error.
2. Identifies the next best free model from the dynamic pool (e.g., switches 
   from `gemini-2.0-flash` to `gemini-1.5-flash` or `gemini-1.5-flash-8b`).
3. Replays your prompt immediately without requiring you to do anything.
4. Displays a non-intrusive status banner indicating which model delivered your 
   script.

RESOLUTION IF ALL MODELS ARE EXHAUSTED:
If you have made a very large number of requests in a single minute across all 
models, wait 30–60 seconds for the free-tier quota window to reset, then click 
"Generate Podcast Script" again.

Q7: A YouTube link shows "No Public Captions Available". What can I do?
--------------------------------------------------------------------------------
CAUSE:
Some YouTube creators disable closed captions, or the video may be music-only.

OPTIONS PROVIDED:
Podcast Studio will never silently bypass access rules or scrape forbidden content. 
Instead, it offers two compliant options:
Option A: Click "Extract Audio & Transcribe Locally". If public audio is accessible, 
          it will stream just the audio track and transcribe it locally on your 
          Mac using Faster-Whisper.
Option B: Click "Upload Video File Instead". If you own the video or have the 
          media file on disk, drag-and-drop it directly into the "Upload" tab.

Q8: Video or audio upload is taking a long time to transcribe. How can I speed 
    it up?
--------------------------------------------------------------------------------
EXPLANATION:
Transcription speed depends on your Mac's hardware (Apple Silicon M-series vs. 
Intel CPU) and the Whisper model size you selected:
- `tiny` model (~75MB): Transcribes 10 minutes of audio in ~5–10 seconds.
- `base` model (~140MB): Recommended balance of speed and punctuation accuracy.
- `small` model (~460MB): Best accuracy for heavy accents or multi-speaker audio.

TIPS:
1. If you are transcribing a 30+ minute video, select the `tiny` or `base` model 
   in the upload dropdown.
2. Once transcribed, remember that the transcript is cached via SHA-256 in 
   `./cache/`. Any subsequent script generation or re-runs will be INSTANT (0 ms).

Q9: How do I change the podcast voices or switch languages?
--------------------------------------------------------------------------------
RESOLUTION:
1. In Step 3 (Script Studio), use the "Language" dropdown to choose English, 
   Spanish, French, German, or Hindi. The script prompt will automatically 
   instruct Gemini to write natively in that language.
2. Under "Voice Casting", choose a voice separately for [Host 1] and [Host 2].
   The free local video options are feminine voices (Jenny, Emily, Aria, Sonia,
   and Natasha) to match the two women shown in the bundled studio footage.
   Voice rate and pitch adjustments help distinguish the hosts.
3. If you select "One Narrator (Solo Deep-Dive)", the second host dropdown is 
   automatically hidden and a solo narrative voice is used.
4. The voice list uses Edge-TTS and does not require a separate API key. The app
   does not include exact actor or movie-character voice copies such as Jarvis,
   Ultron, or Friday.

Q10: Where is the cache stored, and how do I clear it?
--------------------------------------------------------------------------------
EXPLANATION:
All cached transcripts, intermediate chunk summaries, and generated scripts are 
stored as lightweight JSON files in the `./cache/` directory in your workspace.

TO CLEAR CACHE:
- From the UI: Click the small trash icon next to the "Cache: X items" pill in 
  the top navigation header.
- From Terminal: Delete the contents of the cache folder:
  `rm -f cache/*.json`

Q12: What is the difference between free local video and premium video?
--------------------------------------------------------------------------------
FREE LOCAL VIDEO:
The default "Create Video (.MP4)" option renders on your Mac using FFmpeg and
Pillow. It uses bundled free-use footage showing two podcast hosts talking at
microphones, loops the footage for longer episodes, and overlays timed dialogue
captions and speaker labels. The stock hosts are illustrative; their lips are
not synchronized to the generated dialogue. Rendering uses no avatar service,
API key, or paid credits. The footage source and license are listed in
`static/media/ASSET_CREDITS.txt`.

OPTIONAL PREMIUM VIDEO:
Expand "Optional: premium voices & avatars (HeyGen credits)" on the result page.
After configuring a HeyGen API key, load the public and account-owned voice and
avatar lists, choose an avatar and voice for each host, then click "Render
premium video with credits". The script dialogue is sent to HeyGen; that service
creates the avatar video and charges the connected account according to its
current API rates. Credits are not used by the local video button or by loading
the catalog. Check current HeyGen rates before starting a premium render.

Premium Studio renders support up to 50 speaker-turn scenes per video. If the
script exceeds this limit, shorten it before premium rendering.

Q13: How do I enable the optional HeyGen voices and avatars?
--------------------------------------------------------------------------------
RESOLUTION:
1. In Terminal, from the project folder, copy the example configuration:
   `cp .env.example .env`
2. Open `.env` in a text editor and set your HeyGen API key:
   `HEYGEN_API_KEY=your_key_here`
3. Save the file and restart Podcast Studio with `./run_studio.sh`.
4. In the result screen, expand the premium panel and click "Load my HeyGen
   voices and avatars". Then choose the two hosts and render when ready.

The `.env` file contains a private API key and is excluded by `.gitignore`; do
not commit or share it. `.env.example` is only a template and does not contain a
working key. Leave the key unset to use the free local video option.

If the catalog button reports that premium mode is not configured, confirm the
key is in the root project `.env` file and restart the app. The server reads the
key at startup.

Q14: Why is a downloaded MP4 tiny or showing 00:00 duration?
--------------------------------------------------------------------------------
CAUSE:
An earlier or interrupted download may contain only the MP4 header. It is not
the completed video, even if the UI previously displayed a larger render size.

RESOLUTION:
1. Wait until the render has finished and the download link appears.
2. Download the video again from the result screen. Completed local renders are
   published only after FFmpeg finishes writing the file.
3. If the new download is still incomplete, restart the app and render the video
   again. For premium output, check the HeyGen dashboard before retrying so you
   do not submit a second credit-consuming render while the first is still running.

Q15: Which Podcast Studio features need an internet connection?
--------------------------------------------------------------------------------
EXPLANATION:
- **Speech-to-text:** Faster-Whisper runs locally after its model files have
  downloaded once. The first run may need internet to fetch those files.
- **Transcript cache and FFmpeg rendering:** Run locally. Free video uses the
  bundled studio clip and existing MP3, so video rendering itself needs no web
  service or API key.
- **Script generation:** Needs internet to call the Google Gemini API. Enter the
  Gemini key in the app's key settings; it is not the HeyGen key in `.env`.
- **Edge-TTS voice generation:** Needs internet because speech is synthesized
  through Microsoft's Edge TTS service.
- **URL ingestion:** Needs internet to retrieve public page text or YouTube
  captions. Audio extraction from a remote URL also needs network access.
- **Premium HeyGen video:** Needs internet and a configured HeyGen API key;
  renders use the account's credits.
- **Web page appearance:** Tailwind and Lucide are loaded from public CDNs in
  the browser, so an offline browser may show an unstyled interface.

Q16: What is the sandbox, and why can the app have no internet inside it?
--------------------------------------------------------------------------------
EXPLANATION:
A sandbox is an isolated environment used to run commands and edit project files
with controlled access to the filesystem, network, and credentials. This project
folder is writable to the coding agent, but outbound network access can still be
restricted separately. A DNS error means the process could not resolve a host;
it does not necessarily mean your Mac is offline.

There are separate network paths:
- A web-search/browser tool can reach public sites even if a shell command in the
  sandbox cannot. Browsing a site does not give the local app process access.
- The app runs as a local Python process. Its Gemini, Edge-TTS, URL ingestion,
  and first-time dependency downloads require that process to reach their hosts.
- Your normal macOS Terminal runs outside the coding-agent sandbox unless you
  deliberately start the app from a container or another restricted environment.

TO ALLOW NETWORK ACCESS:
1. In the ChatGPT desktop app, use the permissions control below the composer.
   Choose "Ask for approval" and approve a specific network command when asked.
   In the Codex IDE extension, use the permissions control below the composer;
   in Codex CLI, enter `/permissions` to choose an active profile.
2. In ChatGPT Work, when this setting is available, open Settings > Data
   controls > Work network access and turn on "Allow public internet access".
   This controls code and shell access; web search, plugins, and remote browser
   have separate controls. A managed policy may hide or lock the setting.
3. If the prompt or setting is unavailable, ask the environment administrator
   to allow the required destinations. Hosted environments can be enabled,
   disabled, or restricted to an explicit host allowlist. After changing a
   network policy, stop the current shell command and start a new one so the
   refreshed environment applies.
4. To run the app using your Mac's normal network, open Terminal, change to the
   project folder, and run `./run_studio.sh`. Open `http://127.0.0.1:8000` in a
   browser. The server binds only to your own Mac. A VPN, firewall, proxy, or DNS
   issue can still block outbound calls.
5. To check DNS from Terminal, run `nslookup generativelanguage.googleapis.com`.
   If it fails outside the agent too, check your Mac's internet connection,
   VPN/proxy, firewall, and DNS settings.

The network control is separate from the filesystem sandbox and approval policy:
approving a command does not automatically change the permanent network policy.
See the current [Codex sandbox guide](https://developers.openai.com/codex/sandboxing)
for the UI and CLI options supported by your client version.

WEB ACCESS AND WHEN IT IS NEEDED:
- In this coding conversation, web access is provided by the separate web
  search/browser tool. Use it for current facts, project documentation, or a
  public reference URL. Shell network permission is a different capability.
- In Podcast Studio, the app's browser page is local, but script generation,
  neural speech, public URL ingestion, YouTube captions, and remote audio
  extraction need internet access from the running Python server.
- Once Faster-Whisper models are downloaded, transcription can run locally.
  Cached transcripts and video rendering from an existing episode can also run
  offline.

Q17: What was downloaded, configured, and built for this project?
--------------------------------------------------------------------------------
BUILD NOTES:
1. `./run_studio.sh` creates `.venv` and installs Python dependencies from
   `requirements.txt` on first setup, then starts FastAPI/Uvicorn at
   `http://127.0.0.1:8000`. Dependency installation needs package-index access.
2. Gemini creates the podcast dialogue using the key entered in the app. This is
   an external API request. `.env.example` is a template for the optional
   `HEYGEN_API_KEY`; copy it to `.env` only if enabling paid HeyGen video:
   `cp .env.example .env`. The `.env` file is ignored by Git and must stay
   private. `.env.example` is not a real key and does not enable Gemini.
3. Edge-TTS synthesizes the selected free voices over the internet. FFmpeg then
   stitches the resulting audio locally.
4. Faster-Whisper transcribes uploaded media locally after its model is present.
   YouTube captions or public page text can be fetched online before scripting.
5. Free video uses the bundled, compressed Pexels footage documented in
   `static/media/ASSET_CREDITS.txt`. FFmpeg loops the silent clip and combines it
   with the existing episode audio and timed captions. The footage is free to
   reuse under its license; it does not synchronize the hosts' lips to speech.
6. Optional HeyGen rendering sends dialogue to HeyGen and consumes the connected
   account's credits. The local free video path does not call HeyGen.

To make code or asset changes take effect in a running instance, stop the
server with Ctrl+C and start it again using `./run_studio.sh`. Use a regular
Terminal if the agent sandbox cannot reach the network; the sandbox and the
Mac's normal shell have separate network permissions.

Q18: Why did audio synthesis fail with "No audio was received"?
--------------------------------------------------------------------------------
CAUSE:
This message is raised by the Edge-TTS client when its speech request completes
without any audio data. It can happen during a temporary Microsoft speech
service interruption, a dropped/restricted network connection, or when a voice
or text segment is rejected upstream. Recent reports in the Edge-TTS project
describe intermittent failures with otherwise valid requests, so this message
alone does not prove that the script or voice selection is wrong:
https://github.com/rany2/edge-tts/issues/473

HOW THE APP HANDLES IT:
Each dialogue segment is now attempted up to three times, with a short backoff
between attempts. If the retries still return no audio, the error identifies
the host, voice, and segment number. The app only publishes an episode after all
clips have been generated and stitched successfully.

IF IT KEEPS HAPPENING:
1. Confirm the Mac running Podcast Studio has internet access. Web search in the
   coding agent does not prove that the app's Python process can reach Edge-TTS.
2. Retry once after a short wait. If the same voice keeps failing, select another
   free voice and synthesize again.
3. If only one segment fails repeatedly, shorten that spoken turn and remove
   unusual formatting or characters, then retry.
4. Restart the app with `./run_studio.sh` and retry. If the error includes a
   host/voice/segment, include those details when investigating the failure.
